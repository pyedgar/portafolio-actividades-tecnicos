1. Objetivo de la Práctica

El propósito de la Actividad 3 es dominar el flujo colaborativo de trabajo mediante Git y GitHub, estableciendo un esquema ordenado donde cada estudiante trabaje de forma autónoma en una rama dedicada identificada bajo la convención NOMBRE_APELLIDO. En dicha rama se suben los componentes y recursos de la página personal, integrándose posteriormente hacia la rama de producción main.

2. Paso 1: Creación del Repositorio Grupal en GitHub

Se inicializó el repositorio remoto portafolio-actividades-tecnicos bajo el perfil de pyedgar con visibilidad pública. A continuación se presenta la interfaz web oficial de GitHub mostrando las ramas activas del equipo desplegadas:

Captura 1: Vista general del repositorio en GitHub mostrando el menú de ramas activas de los integrantes.

# Inicialización y vinculación remota:
git init
git add .
git commit -m "feat: Inicializar repositorio grupal Los Tecnicos"
git branch -M main
git remote add origin https://github.com/pyedgar/portafolio-actividades-tecnicos.git
git push -u origin main

3. Paso 2: Creación de la Rama Personal de Trabajo en Visual Studio Code

Cumpliendo la instrucción «en una rama que lleve por nombre su nombre y apellido (ej. ALAN_DIAZ)», cada alumno abrió su proyecto en Visual Studio Code y creó su rama individual mediante la terminal integrada:

Captura 2: Visual Studio Code mostrando la creación de la rama EDGAR_REYES en la terminal y el código de la página personal.

  • Comando: git checkout -b EDGAR_REYES genera la rama y realiza la conmutación inmediata.
  • Barra de Estado: En el borde inferior izquierdo de VS Code se aprecia la etiqueta azul confirmando que la rama activa es EDGAR_REYES*.
  • Archivos: Los componentes de la página personal (edgar.html, edgar.css, edgar.ts) quedan aislados en su rama de desarrollo.

4. Paso 3: Subida del Proyecto Personal a GitHub con Git Push

Con los cambios guardados, se agregaron los archivos de la página personal, se creó el commit formal y se realizó el envío remoto a GitHub vinculando la rama remota:

Captura 3: Terminal integrada de Visual Studio Code ejecutando git commit y git push hacia la rama remota en GitHub.

# Comandos ejecutados en la terminal de Visual Studio Code:
git add src/app/componentes/edgar/
git commit -m "Actividad 3: Subir proyecto de pagina personal de Edgar Reyes en rama EDGAR_REYES"
git push -u origin EDGAR_REYES

6. Paso 5: Fusión de Ramas (Merge) hacia la Rama Principal Main

Para consolidar todas las páginas en el portafolio grupal y que queden publicadas en Internet en GitHub Pages, se integraron los cambios con una fusión Fast-Forward sin colisiones:

Captura 5: Visual Studio Code mostrando la integración de la rama mediante Fast-Forward merge hacia main.

# Protocolo de integración hacia main:
git checkout main
git pull origin main
git merge origin/EDGAR_REYES
git push origin main

7. Buenas Prácticas

  • Nomenclatura uniforme: Respetar el formato NOMBRE_APELLIDO asegura uniformidad institucional.
  • Sincronización continua: Ejecutar git pull origin main antes de iniciar cualquier cambio local.
  • Commits descriptivos: Detallar en el mensaje el archivo y la actividad que se está subiendo.
